### 규모
| 항목 | 이 테스트 | 실제 | 축소 비율 |
|---|---|---|---|
| 유저 | 500 (시드 `seed0001` ~ `seed0500`) | 250만 | 1 / 5,000 |
| 그룹 | 87 (2 ~ 10명, 평균 5.7) | 25만 ~ 125만 | 약 1 / 3,000 ~ 1 / 14,000 |

- 시드 계정은 같은 계정 두 번 로그인 금지 (409) → 가상 유저 1명 = 계정 1개, 500명이 상한
- 그래서 「사람 수」 대신 「동시성을 몰아서」 단위 처리량과 한계를 재고, 실제 규모는 산술로 추정

### 도구
| 항목 | 내용 |
|---|---|
| 부하 도구 | 직접 만든 Go 도구 `tool/` (표준 라이브러리만), `run.sh` 가 빌드 → `docker run --rm` |
| 시계 | `POST /api/v1/dev/clock` 으로 07:00 의 10초 전, 08:00 의 10초 전으로 이동 |
| 서버 쪽 수집 | Redis `CONFIG RESETSTAT` → `INFO commandstats/stats/cpu/memory`, `SLOWLOG` (문턱 0, 끝나면 원래 값 복구) |
| persister 적체 | `ev:{0..1023}` 의 `XLEN`, `XINFO GROUPS` (pending, lag, entries-read) 0.5초마다 |
| 자원 | `docker stats` 약 1 ~ 2초 간격, PG `pg_stat_database`, `pg_stat_activity`, `pg_stat_user_tables` 0.5초 간격 |
| 검증 | 끝난 뒤 PG `solve_signals`, `group_results`, `daily_progress` 를 SQL 로 대조 (`db_checks.txt`) |

**k6 를 안 쓴 이유** — 이 머신에 k6 v2.2.0 이 설치돼 있었고 확인함

| 이유 | 내용 |
|---|---|
| SSE 팬아웃 지연 | 「A 풀이 → 같은 그룹 B 의 SSE 수신」 을 재야 함. k6 본체는 SSE 미지원, `xk6-sse` 확장 빌드 필요 |
| 그룹원끼리 맞물림 | A 의 풀이 보낸 시각과 B 의 수신 시각을 같은 프로세스 메모리에서 짝지어야 함 (VU 사이 상태 공유) |
| 같은 시간축 수집 | 구간 시작 순간에 Redis `RESETSTAT`, `SLOWLOG RESET`, 끝에 `INFO` 를 도구가 직접 RESP 로 호출 |
| 대가 | 측정 정확성을 스스로 검증해야 함 → 아래로 검증 |

## 7. 재현

```bash
# delightroom-test 루트에서 스택이 떠 있어야 함
./iac/local.sh up

# 이 폴더에서
./run.sh day     # ① ② ③, 시드 500명, 약 3분
./run.sh bank    # ④, 다음 게임 날짜, 약 4분
python3 -I analyze.py results/<run>   # 구간별 docker stats, PG 증가량
```

| 파일 | 내용 |
|---|---|
| `tool/` | Go 부하 도구 (`main.go` 시나리오, `sse.go` SSE 수신, `redis.go` Redis 측정, `common.go` HTTP) |
| `run.sh` | 환경 기록, 빌드, 시계 이동, 샘플러, 실행, DB 대조, 정리 (`trap`) |
| `analyze.py` | 샘플러 원본을 구간으로 자름 → `phase_resources.txt` |
| `results/*/p*_summary.json` | 구간별 지연 분포 (전체 요청 기준) |
| `results/*/p*_raw.csv` | 요청별 원본 (5만 건 넘으면 표본, 머리줄에 비율) |
| `results/*/*_redis.json` | Redis INFO, Lua 스크립트별 통계, persister 적체 요약 |
| `results/*/day_stream.csv`, `p4_stream.csv` | persister 적체 0.5초 시계열 |
| `results/*/docker_stats.csv`, `pg_stats.csv` | 자원, PG 원본 |
| `results/*/db_checks.txt`, `p2_pg_reflect.txt`, `worker_jobs.log` | PG 대조, 반영 지연, worker 잡 로그 |
