판 v3.6 · 2026-11-11 (v3.6: T-WC-7 — O45 정리 조건에 네트워크 · 이번 태그 이미지 · 실패 경로 · 전용 프로젝트 <프로젝트>-e2e(LLD §3.8) · v3.5: I6 의 grep 은 앱 코드만 — 테스트 파일(*.test.ts(x))은 저장 여부를 확인하려고 localStorage 를 읽으므로 뺀다 · v3.4: O15 — refresh 를 부르지 않는 것은 /auth/signup · login · refresh · logout 의 401, /auth/me 401 은 refresh(SPEC W18 v5.4) · v3.3: 확인 명령을 pnpm test -t <id> 로(-- 를 넣으면 필터가 vitest 에 안 가 전부 돈다) · 통과 수 > 0 조건 · O36 에 끝난 스트림 뒤 결과 다시 읽기 · v3.2: 「나」는 /auth/me(prd D23) — O19 · O20 · O22 · I6 에서 gm:me 를 뺌 · v3.1: O23 · O24 를 서버와 같은 공유 벡터 docs/api/answer-normalization-vectors.json(prd D22)으로 · v3: 서버 연동 기준 O13 ~ O45 · 불변식 I6 ~ I10 · 확인 명령에 pnpm test(Vitest) · pnpm e2e(Playwright · compose) · O2 는 지면 View 스토리로 · v2: 판정 밖의 서버 계약 문구를 대응표로) · 짝 문서: HLD · LLD · SPEC

세 줄 요약

  • 기준 45개(O1 ~ O12 시안 · O13 ~ O45 연동) + 불변식 10개(I1 ~ I10). 일감 T-WC-1 ~ T-WC-7 이 각자 기준을 맡는다(tasks §1.7).
  • 확인 명령: frontend/ 에서 pnpm typecheck · pnpm lint · pnpm test · pnpm build · pnpm build-storybook, 종단은 pnpm e2e(compose 를 띄우고 내린다).
  • 단위 테스트 이름은 기준 id 로 시작한다(예: it('O15 동시 401 세 건에 refresh 한 번', …)). 픽셀 일치 · 운영 규모는 판정 밖.

3. 판정 밖

  • 픽셀 단위 일치 — 덩어리 · 문구 · 토큰 값으로 대조한다.
  • 운영 규모(동시 접속 수 · 프록시 성능) · HTTPS · 실제 네트워크 지연 — 로컬 compose 로만 본다.
  • 서버 정합성(멱등 · 마감 · 랭킹) — 서버 기능 ORACLE 이 판정한다. 이 문서는 클라이언트가 계약대로 부르는지만 본다.
  • 정규화의 정확한 문자 목록은 prd D22 가 정본이다 — 이 문서는 그 표와 같은 벡터를 쓰는지만 본다.
