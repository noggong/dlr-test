105:### 6.2 규칙
108:| P9 | 꺼진 앱(운영 기본)은 런타임 이동량이 0 이고 Redis 키 `demo:clock` 을 읽지도 쓰지도 않는다. `GET` · `POST /api/v1/dev/clock` 라우트가 없고 인증 예외도 없다 — 쿠키가 없으면 다른 보호 경로처럼 `401 UNAUTHORIZED`, 있으면 404(Spring 기본 본문 — P5 의 예외) |
109:| P10 | 첫 이동량: 빈 볼륨의 첫 기동 시각 `r` 에서 `r + lead` = 게임 `D 07:00` 이 되게 한다. `D` 는 이동 총량(`clock-offset` + 이동량)이 10분(`start-time − join-cutoff`) 이상이고 이동량이 0 이상인 가장 이른 날짜다 — 07:00 전에 가입한 테스트 사용자는 모두 `D` 의 그룹원이다(prd D24 · `joined_at` 은 실제 시각). 이미 키가 있으면(볼륨이 남음) 그 값을 쓴다. 한계: 07:00 뒤 새 그룹을 만든 가입자도 요청 때 만든 명단에 들 수 있다(LLD §4.4-5) |
110:| P11 | 세 앱은 같은 키를 읽는다. 시각 이동을 받은 `api` 는 바로, 다른 앱은 `sync-interval`(1초) 안에 따라온다. 앱의 이동량은 커질 때만 반영한다 — 키가 없거나 더 작으면 그 앱 값을 다시 심는다(시각이 뒤로 가지 않는다) |
111:| P12 | 시각 이동은 앞으로만, 그리고 `now` 뒤 가장 이른 경계(07:00 · 08:00 · 08:00:03) − `move-margin` 까지만이다. 경계는 실제 시간이 흘러 지나간다 |
112:| P13 | `worker` 의 잡(07:00 명단 · 06:30 · 06:50 은행 · 08:00 · 08:00:03 마감)은 이동 뒤 `sync-interval` + 1초 안에 다음 실행 시각을 다시 고른다 — 시각이 지났으면 곧바로 돈다 |
113:| P14 | 시각 이동 API 는 인증을 요구하지 않는다 — 로컬 전용이고 꺼지면 라우트도 인증 예외도 없다(P9) |
114:| P15 | 이동이 성공하면 모든 로그인 세션 키(`sess:{<uid>}`)의 남은 TTL 을 이동량만큼 줄인다 — refresh token 만료(게임 시각)와 맞춰, 하루를 옮긴 뒤 다시 로그인이 `409 ALREADY_LOGGED_IN` 으로 막히지 않게. access token 은 이동만큼 일찍 만료되고 클라이언트는 refresh 한다 |

**세 줄 요약**
- 기능 6개(platform · auth-signup · game-session · solve-signal · realtime-board · deadline-result)의 LLD 「구현 순서」를 하루 크기의 일감 44개로 묶었다. web-client 서버 연동은 일감 8개(T-WC-1 ~ T-WC-8 · §1.7)로 따로 둔다. 일감마다 「끝났다」를 판정하는 ORACLE 기준 id 와 확인 명령을 붙였다.
- 의존을 따라 9단계로 나뉜다. 같은 단계의 일감은 병렬로 할 수 있다. 가장 긴 사슬은 가입 → 스키마 → 게임 세션 → 재적재다.
- 판정할 ORACLE 기준이 없는 것은 그대로 「기준 없음 — 보강 필요」로 적었다. G1(250만 규모), G3 종단 전달, G4 「묻지 않고 개발」, NFR-5 재적재가 여기에 해당한다(§5 · §6).

## 0. 읽는 법
| 항목 | 규칙 |
|---|---|
| id | `T-<기능약자>-<번호>`. 약자는 PF = platform · AU = auth-signup · GS = game-session · SS = solve-signal · RB = realtime-board · DR = deadline-result · WC = web-client(선택) |
| 정의 | 무엇을 만드는지, 어디까지 하는지를 파일 · 모듈 수준으로 적는다. 경로의 정본은 각 LLD §1 이다 |
| 근거 | `LLD <기능> §n` · `구현 순서 k` = 그 LLD 「구현 순서」의 k단계. SPEC 규칙 id(AS · GS · SS · RB · DR · P)를 함께 적는다 |
| 성공 지표 | 그 기능 ORACLE 의 기준 id(O · I), 확인 명령 한 줄, 통과 조건 요약을 적는다. 통과 조건의 정본은 ORACLE 표다. 기준 id 앞에 기능 이름이 없으면 그 일감이 속한 기능의 ORACLE 이다 |
| 공통 통과 조건 | 명령 종료 코드 0 + ORACLE 표의 「통과 조건」. 테스트 이름은 기준 id 로 시작한다(각 ORACLE §0 규약) |
