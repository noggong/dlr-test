412:### 4.2 재적재 (rehydrate — T-PF-5)
420:3. **마감 따라잡기(`worker: member` 만)**: 지금 ≥ `D 08:00` 이면 재적재 판정이 참인(기록이 있는) 2명 이상 그룹 **모두** 에 Lua `deadline`(1차 — `t ≥ 08:00:03` 이면 Lua 가 확정까지 한다)을 부른다(`GroupDayRepository.runDeadline`) — 이번 호출이 만들었는지(`created`)와 상관없다. 페이지를 다시 돌거나 앞 실행의 따라잡기가 실패했어도 빠지지 않게 하려는 것이고, Lua `deadline` 이 멱등이라(이미 처리된 그룹은 `SKIPPED`) 겹쳐도 같다. `SKIPPED` 가 아닌 결과만 「따라잡음」으로 센다. 끝내 실패하면 그 실행을 실패로 세어 표시를 쓰지 않는다. 결과 없는 그룹은 확정(`group.decided`) · 미룸(`pending`), 결과 있는 그룹은 08:00:03 뒤면 랭킹 확정(`group.ranking_final`). 08:00 · 08:00:03 의 마감 잡이 그 그룹을 이미 지나간 뒤라서다. `api` 경로는 08:00 전에만 재적재하므로 마감 잡이 그 그룹을 목록에서 찾는다.
422:**재적재 판정** — R1 에 그 그룹의 행이 하나라도 있거나 R2 에 결과가 있으면 「전에 명단이 있었다」(Q10 의 -1 행은 명단을 만든 뒤에만 들어간다 — game-session §3.4-3 · §3.5-4). 아니면 처음 만드는 명단이라 지금과 같이 `version 0` · 그룹원 -1 · `NOT_STARTED` 다(07:00 정상 실행).
442:- **`version`**: 옛 값은 PostgreSQL 에 없다(이벤트의 `version` 은 기록하지 않는다). 열린 SSE 연결은 `version ≤ lastVersion` 인 메시지를 버리므로(realtime-board LLD §3) 옛 값보다 작게 올리면 현황판이 멈춘다. 그래서 epoch ms(13자리 ≈ 1.8×10¹²)를 쓴다 — 그룹 하루 변경 수(그룹원 10명 × 몇 번 + 마감 몇 번 = 백 단위)보다 훨씬 커 FLUSH 전 어떤 값보다 크고, 두 번째 재적재의 값도 첫 재적재 뒤 늘어난 수(경과 ms 보다 작다)보다 크다. µs 는 쓰지 않는다 — 채널 메시지(`common.publish`)의 cjson 이 숫자를 14자리로 줄여 16자리 µs 를 잃는다. 재적재 자체는 publish 하지 않는다 — 다음 변경이 큰 `version` 으로 나가고, 새 연결은 스냅샷을 받는다.
452:- 출제 중복 — `served_questions` 는 평생 키 (user_id, question_id) 라 다른 날 이미 낸 문제를 다시 냈으면 처음 기록(다른 날짜 · 번호)만 남는다(game-session §3.7). 그날 그 번호의 `cur` 가 없으므로 그 유저는 문제 화면에 다시 들어와 진입 신호로 다시 고정해야 하고(shown 6 — 그 전의 풀이는 `QUESTION_MISMATCH`), 08:00 미룸 판정에서 「3번 지금 문제 있음」으로 세지 않는다. 드문 운영 이상이다.
456:- 08:00 뒤 Redis 와 `worker` 가 **함께** 재시작되면(호스트 재부팅) 그 프로세스는 표시를 본 적이 없어 감시가 돌지 않고, 마감 잡의 재기동 재실행도 그날 그룹 목록이 비어 아무것도 못 한다 — 그 시점에 결과가 PostgreSQL 에 없던 그룹(마감 처리 전 · persister 가 못 씀)은 결과가 없다. 결과 조회는 PostgreSQL 에 있는 결과를 그대로 준다. 기동 때 표시가 없어도 R1 기록이 있는 그룹만 올리는 「재적재 전용 실행」으로 메울 수 있으나 이번 판에서는 하지 않는다(남은 판단거리).

#!/usr/bin/env bash
# 백엔드 Gradle 명령을 JDK 21 컨테이너에서 돌린다 — 호스트에 JDK 21 이 없어도 된다.
# Testcontainers 는 호스트 Docker 를 쓴다(소켓 마운트). 워크트리에서도 그 워크트리의 backend/ 를 돌린다.
#
#   ./iac/test.sh                                   ./gradlew test (전체)
#   ./iac/test.sh :core:domain:test --tests '…'     원하는 Gradle 인자 그대로
#
# Gradle 캐시는 이름 있는 볼륨 dr-gradle-cache 에 둔다. 지우려면: docker volume rm dr-gradle-cache
set -euo pipefail
ROOT=$(cd "$(dirname "$0")/.." && pwd)
if [ $# -eq 0 ]; then set -- test; fi
# 워크트리 여러 곳이 같은 캐시 볼륨을 쓰면 Gradle 이 캐시 잠금을 기다리다 시작도 못 하고 실패한다
# (「Timeout waiting to lock」). 그 경우에만 잠시 쉬었다가 최대 5번 다시 돈다 — 다른 실패는 그대로 낸다.
LOG=$(mktemp)
trap 'rm -f "$LOG"' EXIT
for attempt in 1 2 3 4 5; do
  set +e
  docker run --rm \
    -v "$ROOT":/repo -w /repo/backend \
    -v dr-gradle-cache:/root/.gradle \
    -v /var/run/docker.sock:/var/run/docker.sock \
    -e TESTCONTAINERS_HOST_OVERRIDE=host.docker.internal \
    eclipse-temurin:21-jdk ./gradlew --no-daemon "$@" 2>&1 | tee "$LOG"
  code=${PIPESTATUS[0]}
  set -e
  if [ "$code" -eq 0 ] || ! grep -q "Timeout waiting to lock" "$LOG"; then exit "$code"; fi
  echo "[iac/test.sh] Gradle 캐시 잠금 대기 초과 — $((attempt * 20))초 뒤 다시 시도 ($attempt/5)" >&2
  sleep $((attempt * 20))
done
exit "$code"
# 진입점 — 실제 정의는 iac/compose.yaml. 레포 루트에서 `docker compose up --build` 한 번으로 모든 서비스가 뜬다(prd §10).
