     1	# HLD — 그룹 미션 웹 클라이언트 (시안 퍼블리시)
     2	
     3	> 판 v2 · 2026-11-11 (v2: 시안 경로를 레포 안 보관본으로 · PRD 결정 D2~D5 반영 · 서버 계약 대응표는 SPEC §2) · 짝 문서: [LLD](../lld/web-client.md) · [SPEC](../spec/web-client.md) · [ORACLE](../oracle/web-client.md)
     4	
     5	**세 줄 요약**
     6	- 웹 디자이너 시안(지면 7장 · 상태 23개)을 React SPA 로 옮겨, 클라이언트 개발자가 화면과 상태 전이를 실물로 확인하게 한다. API · 실시간 연결 없이 목 데이터로 돈다.
     7	- 공용 컴포넌트 13종을 먼저 만들고 지면은 그 조합만 한다 — 같은 기능을 두 벌 만들지 않는다. 지면 상태는 쿼리스트링 `state` 하나로 고른다.
     8	- 가장 큰 위험은 시안과 구현이 어긋나는 것. 디자인 토큰을 `tokens.html` 값 그대로 CSS 변수로 옮기고, 23개 상태를 경로 표(SPEC §1)로 묶어 빠짐을 막는다.
     9	
    10	## 1. 배경 · 목표
    11	- PRD §9.3 · 목표 G4: 클라이언트 개발자가 서버 개발자에게 묻지 않고 개발을 시작할 수 있어야 한다. PRD 상 클라이언트 구현은 범위 밖(§10)이므로, 이 모듈은 **데모 · 검증용 퍼블리시**다.
    12	- 근거 자료: 웹 디자인 시안 보관본 `docs/outputs/feature-web-design/designs/` — `tokens.html` · `mockups/{signup,login,waiting,play,done,result,solo}.html` · `flow/main.html`. 시안은 PRD v2 · 결정 D1 과 대조됐고, 시안이 정한 화면 규칙은 PRD v3 결정 D2~D5 로 확정됐다.
    13	- 목표
    14	  - 시안의 23개 상태를 모두 경로 + 쿼리스트링으로 재현한다(모바일 390 · PC 1280 양쪽).
    15	  - 화면 규칙(정책)을 컴포넌트에 넣는다: 상태 3색, 진행도 -1 → 0/3, 패스 하루 1번 잠금, 08:00 잠금, 부정 실패자 표시 규칙.
    16	  - 컴포넌트마다 Storybook 스토리로 상태를 미리 본다.
    17	- 목표 아님
    18	  - API 호출 · 실시간 연결 · 로컬 스토리지 실연동 · 정답 해시 판정 · 상태 관리 라이브러리 · 자동 테스트.
    19	  - 서버 연동. 서버 계약은 `docs/api/openapi.yaml` · `docs/api/asyncapi.yaml` 이다. 목 데이터 필드는 서버 계약과 이름이 다르고, 대응은 SPEC §2 의 표 한 곳에 둔다 — 연동할 때 그 표대로 바꾼다.
    20	
    21	## 2. 구성 요소
    22	| 구성 요소 | 책임 | 의존 |
    23	|---|---|---|
    24	| 디자인 토큰 (`src/styles/tokens.css` · `tailwind.config.ts`) | 색(라이트/다크) · 글꼴 · 라운드 · 그림자 · 컨테이너 쿼리 768 기준 | `tokens.html` 값 |
    25	| 공용 컴포넌트 (`src/components/`) | AppShell/TopBar · Button · Field/Input · SegmentedControl · StatusChip · ProgressBar · Board · QuestionCard · Callout · Sheet/Modal · Toast · Countdown · Skeleton (+ Icon · Hero · Card 같은 바탕 부품) | 토큰 |
    26	| 지면 (`src/pages/`) | 지면 7개. 상태를 받아 공용 컴포넌트를 배치만 한다 | 공용 컴포넌트 · 목 데이터 |
    27	| 목 데이터 (`src/mocks/*.json`) | 지면 × 상태별 고정값. 서버가 줄 모양(그룹원 · 진행도 · 상태 · 랭킹 · 시각)을 흉내 낸다 | — |
    28	| 라우터 (`src/App.tsx`) | 지면마다 경로 1개 · `state` 쿼리 파싱 · 알 수 없는 경로는 첫 지면으로 | React Router |
    29	| Storybook (`.storybook/`) | 컴포넌트별 상태 미리보기 | 토큰 · 컴포넌트 |

    31	## 3. 흐름
    32	1. 사용자가 `/quiz?state=pass` 처럼 경로와 상태를 연다.
    33	2. 지면이 `useScreenState(허용 목록, 기본값)` 으로 `state` 를 읽는다 — 목록 밖 값이면 기본 상태.
    34	3. `state=loading` 이면 같은 자리에 뼈대(Skeleton)를, `state=empty` 면 빈 상태 한 줄(Callout)을 세운다(자리를 바꾸지 않는다 — tokens.html 「로딩 · 빈 상태」).
    35	4. 그 밖이면 목 데이터에서 그 상태의 묶음을 꺼내 공용 컴포넌트로 그린다.
    36	5. 지면 안의 버튼 · 링크는 플로우맵(`flow/main.html`)의 배선대로 다른 경로 · 상태로 옮긴다(예: 패스 버튼 → `?state=pass`, 패스하기 → `?state=passed`, 결과 보기 → `/result?state=ok`).
    37	
    38	## 4. 정합성 · 동시성
    39	서버 정합성은 이 모듈의 몫이 아니다. 화면 쪽에서 지킬 불변식만 둔다.
    40	- 상태 표기는 `진행 중(ing) · 성공(ok) · 실패(bad)` 셋뿐 — StatusChip 의 tone 타입이 이 셋(+ 장식용 mute · acc)으로 닫혀 있다.
    41	- 진행도 -1 은 화면에 `0/3` — ProgressBar 가 입력을 0~3 으로 깎는다.
    42	- 패스를 쓴 날은 끝까지 「패스 사용함」 잠긴 버튼 — 퀴즈 상태 `passed` 이후(`live` · `last` · `warn` · `closed`)는 모두 `passUsed: true` 데이터로 그린다.
    43	- 08:00(`closed`)에는 입력 · 패스 · 제출이 모두 `disabled`.
    44	- 08:00 전 현황판의 부정 실패자: 칩은 「진행 중」, 진행도는 실패 시점 값, 순위는 맨 아래(PRD 결정 D2). 그룹 결과 확정 뒤에는 「실패」.
    45	- 순위는 목 데이터에 계산된 값으로 싣는다(랭킹 계산은 서버 몫 · PRD §6). 클라이언트는 받은 순서대로 그린다.
    46	
    47	## 5. 결정과 버린 대안
    48	| 결정 | 고른 것 | 버린 대안 | 근거 |
    49	|---|---|---|---|
    50	| 모듈 위치 | 모노레포 `frontend/` 한 모듈(pnpm 단독 패키지) | 루트에 바로 Vite 프로젝트 · pnpm workspace 루트 | 백엔드(`backend/` · Gradle) · 인프라(`iac/`)와 나란히 둔다. 언어가 달라 루트 workspace 로 묶지 않는다 |
    51	| 토큰 전달 | CSS 변수(라이트 · `prefers-color-scheme: dark`) + Tailwind 가 변수를 참조 | Tailwind `dark:` 변형으로 색을 두 벌 적기 | 시안 정본이 CSS 변수라 값이 1:1 로 옮겨지고, 다크 전환이 클래스 없이 된다 |
    52	| 반응형 기준 | 앱 틀의 **컨테이너 쿼리 768**(`@container`) | 뷰포트 미디어 쿼리 | 시안이 컨테이너 쿼리로 정의됨(「기준은 화면 폭이 아니라 앱 틀의 폭」). Storybook 안에서도 같은 기준으로 보인다 |
    53	| 상태 전환 | 쿼리스트링 `state` | 경로 세그먼트(`/quiz/pass`) · 전역 상태 | 요청 스펙. 지면마다 경로 1개를 지킨다 |
    54	| 지면 상태 | 지면마다 상태 → 목 데이터 묶음 표 | 상태를 컴포넌트 안 조건문으로 흩기 | 23개 상태를 한 표(SPEC §1)와 목 JSON 에서 대조할 수 있다 |
    55	| 아이콘 | 시안의 인라인 SVG 를 `Icon` 한 컴포넌트로 | 아이콘 라이브러리 | 외부 의존 0, 시안과 같은 선 |
    56	| 시계 | 화면에 고정 시각(목 데이터) — Countdown 은 남은 초를 받아 1초씩 줄인다 | 실제 시계 · 시각 주입 | API 없는 데모라 상태 재현이 우선. 카운트다운은 움직이는 것만 보여 준다 |
    57	
    58	## 6. 위험 · 열린 질문
    59	- 목 데이터 필드 이름이 서버 계약과 다르다 — 대응표(SPEC §2)와 목 데이터 타입(`src/mocks/types.ts`) 한 곳만 바꾸면 되도록 묶어 두었다.
    60	- `state=empty` 의 뜻은 시안에 지면별로 정의되지 않았다(tokens.html 의 원칙만 있음). 이 문서는 「현황판 · 그룹원 자리에 데이터가 없을 때 그 자리에 안내 한 줄」로 정했다(SPEC §1).
    61	- 부정행위 경고(`warn`)는 실제로는 `beforeunload` · `visibilitychange` 에서 띄우지만, 이번 범위는 상태로 보여 주는 것까지다.

    59	## 3. 처리 절차
    60	1. `main.tsx` 가 `BrowserRouter` 로 `App` 을 띄우고, `App` 은 경로 → 지면 표를 둔다(`/` · 모르는 경로 → `/login`).
    61	2. 지면은 `const state = useScreenState(['start', ...], 'start')` 로 상태를 정한다. `loading` · `empty` 는 공통으로 허용한다.
    62	3. 지면은 목 데이터 `data[state]` 를 꺼내 `AppShell` 안에 공용 컴포넌트를 놓는다. 지면 파일에는 스타일 클래스를 최소로 두고 배치만 한다.
    63	4. 버튼은 SPEC §4 의 배선대로 `useNavigate` / `Link` 로 다른 상태를 연다.
    64	5. 반응형은 `AppShell` 이 `@container` 를 세우고, 컴포넌트는 `@pc:` 변형(앱 틀 폭 768 이상)으로 PC 값을 준다.
