# SPEC — game-session

> 판 v1 · 2026-11-11 · 짝 문서: [HLD](../hld/game-session.md) · [LLD](../lld/game-session.md) · [SPEC](../spec/game-session.md) · [ORACLE](../oracle/game-session.md) · 근거: [PRD](../prd.md) v10 FR-1 · FR-3 · §5.2 · D6 · D8 · D10 · D14 · D15 · D18 · 공통 규약: [API 가이드](../api-guide.md)

**세 줄 요약**
- 외부 계약은 `api` 엔드포인트 3개 — 게임 정보 `GET /api/v1/games/today` · 문제은행(= 미션 시작) `POST /api/v1/games/today/question-bank` · 진입 신호 `POST /api/v1/games/today/shown`. 셋 다 쿠키 `access` 필수.
- 입력 검증은 진입 신호 본문뿐이다(`questionNo` 1 · 2 · 3, `questionId` 64자 소문자 hex). 시간 창은 07:00:00 ≤ 서버 시각 < 08:00:00(Redis `TIME`), 유예 없음.
- 오류 코드: `INVALID_REQUEST` · `UNAUTHORIZED` · `GAME_NOT_OPEN` · `SUBMISSION_CLOSED` · `NOT_PARTICIPANT` · `SOLO_GROUP` · `QUESTIONS_EXHAUSTED` · `MISSION_NOT_STARTED` · `MISSION_ALREADY_FINISHED` · `QUESTION_MISMATCH` · `QUESTION_OUT_OF_ORDER`(뜻은 api-guide §4). 규칙은 §3 의 GS1 ~ GS14.

## 1. 엔드포인트
| 메서드 | 경로 | 인증 | 설명 | 규칙 |
|---|---|---|---|---|
| GET | `/api/v1/games/today` | 쿠키 `access` | 게임 날짜 · 시작 · 마감 · 서버 시각 · 그룹명 · 그날 그룹원 | GS1 · GS3 |
| POST | `/api/v1/games/today/question-bank` | 쿠키 `access` | 문제은행 받기. 그날 처음 받은 순간이 미션 시작 | GS2 ~ GS8 · GS14 |
| POST | `/api/v1/games/today/shown` | 쿠키 `access` | 진입 신호 — 이 번호의 지금 문제를 고정 | GS2 · GS3 · GS4 · GS9 ~ GS13 |

공통: 본문은 `application/json; charset=utf-8`, 시각은 ISO-8601 `+09:00`, 날짜는 `YYYY-MM-DD`(KST 게임 날짜). 오류 본문은 언제나 `{ "code": string(ErrorCode), "message": string }` 이고 클라이언트는 `code` 로만 분기한다. 쿠키 `access` 가 없거나 만료 · 위조면 모든 엔드포인트가 `401 UNAUTHORIZED` 다(가장 먼저 본다).

## 2. 요청 · 응답

### 2.1 `GET /api/v1/games/today` — 게임 정보
앱을 열 때 · 대기 화면 카운트다운에 쓴다. 상태를 바꾸지 않는다. 07:00 전에는 「지금까지 그 날짜 07:00 전에 가입한 사람」, 07:00 이후에는 07:00 에 확정된 그날 그룹원이다(GS3). 08:00 이후에는 다음 날 게임을 준다(GS1).

**요청**
| 위치 | 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|---|
| 헤더 | `Cookie: access=<JWT>` | string | 예 | 유효한 access token | 로그인 쿠키 |
| 쿼리 · 본문 | — | — | — | — | 없다 |

**응답 `200`**
| 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `date` | string(date) | 예 | `YYYY-MM-DD` | 게임 날짜(GS1) |
| `startAt` | string(date-time) | 예 | `date` 의 07:00:00+09:00 | 미션 시작 시각 |
| `deadlineAt` | string(date-time) | 예 | `date` 의 08:00:00+09:00 | 마감 시각(제출 유예는 solve-signal 의 D1) |
| `serverTime` | string(date-time) | 예 | 밀리초까지 | 응답을 만든 서버 시각 — 클라이언트 카운트다운의 기준(기기 시계를 쓰지 않는다) |
| `group` | object | 예 | | 내 그룹 |
| `group.name` | string | 예 | 2~20자 | 그룹명(가입 때 입력 표기 — prd D11) |
| `group.members` | array | 예 | 0~10개, `userId` 오름차순 | 그날 그룹원(GS3). 내가 07:00 이후 가입했으면 나는 없다. 1개면 1명 그룹(GS4) |
| `group.members[].userId` | string | 예 | `^[a-z0-9_]{4,20}$` | 로그인 아이디(prd D5) |

**오류**
| code | HTTP | 조건 |
|---|---|---|
| `UNAUTHORIZED` | 401 | `access` 없음 · 만료 · 위조 |

**요청 예시**
```bash
curl -s -b 'access=<JWT>' http://localhost:8080/api/v1/games/today
```

**응답 예시** `200` (06:55 — 07:00 전)
```json
{
  "date": "2026-11-12",
  "startAt": "2026-11-12T07:00:00+09:00",
  "deadlineAt": "2026-11-12T08:00:00+09:00",
  "serverTime": "2026-11-12T06:55:12.345+09:00",
  "group": {
    "name": "아침수영",
    "members": [{ "userId": "dohyun" }, { "userId": "jiwoo_k" }, { "userId": "minseo01" }]
  }
}
```

### 2.2 `POST /api/v1/games/today/question-bank` — 문제은행(= 미션 시작)
그날 처음 성공한 호출이 미션 시작이다(진행도 -1 → 0, 상태 `IN_PROGRESS`, 시작 시각 · 지각 고정 — GS5). 같은 날 다시 부르면(재접속 · 재시도) 아무것도 바꾸지 않고 같은 시작 시각 · 같은 은행을 준다(GS7). 상태를 바꾸므로 POST 다.

**요청**
| 위치 | 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|---|
| 헤더 | `Cookie: access=<JWT>` | string | 예 | 유효한 access token | 로그인 쿠키 |
| 본문 | — | — | — | 비워 보낸다(보내도 무시) | 없다 |

**응답 `200`**
| 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `missionStartedAt` | string(date-time) | 예 | 그날 07:00:00 ≤ 값 < 08:00:00, 마이크로초까지 | 그날 미션 시작 시각 — 처음 받은 순간의 서버 시각(Redis `TIME`). 다시 받아도 같은 값 |
| `questions` | array | 예 | 3~60개. 난이도 1 → 2 → 3 순서, 난이도마다 1~20개 | 문제은행(GS6) |
| `questions[].questionId` | string | 예 | `^[0-9a-f]{64}$` | 문제 PK(hash) — 진입 · 풀이 · 패스 신호에 그대로 보낸다 |
| `questions[].difficulty` | integer | 예 | `1` · `2` · `3` | 난이도 = 그 문제를 낼 번호(R-B5) |
| `questions[].body` | string | 예 | 비어 있지 않음 | 문제 본문(주관식) |
| `questions[].category` | string(enum) | 예 | `CURRENT` · `POLITICS` · `SOCIETY` · `GENERAL` | 분야 — 시사 · 정치 · 사회 · 상식 |
| `questions[].answerHash` | string | 예 | `^[0-9a-f]{64}$` | 정답 해시 = `SHA-256(UTF-8("<questionId>:<정규화한 답>"))` 소문자 hex(prd D7). 실제 정답은 내려주지 않는다 |

**오류** (판정 순서는 GS14)
| code | HTTP | 조건 |
|---|---|---|
| `UNAUTHORIZED` | 401 | `access` 없음 · 만료 · 위조 |
| `GAME_NOT_OPEN` | 409 | 서버 시각 < 그날 07:00:00 (D14) |
| `SUBMISSION_CLOSED` | 409 | 서버 시각 ≥ 그날 08:00:00 |
| `NOT_PARTICIPANT` | 403 | 그날 그룹원이 아님 — 그날 07:00 이후 가입(GS3) |
| `SOLO_GROUP` | 409 | 그날 그룹원이 1명(GS4) |
| `QUESTIONS_EXHAUSTED` | 409 | 은행을 새로 만들어야 하는데 어떤 난이도의 미출제 문제가 0개(GS6). 미션 시작은 이미 반영돼 있다(GS5) |

**요청 예시**
```bash
curl -s -X POST -b 'access=<JWT>' http://localhost:8080/api/v1/games/today/question-bank
```

**응답 예시** `200` (난이도마다 1개로 줄여 보인다 — 실제는 난이도마다 최대 20개)
```json
{
  "missionStartedAt": "2026-11-12T07:00:01.204518+09:00",
  "questions": [
    {
      "questionId": "032a4ed4d015d003a07a04124ce2b3513e71b986c3cf279104111ced399b366f",
      "difficulty": 1,
      "body": "대한민국 국회의원의 임기는 몇 년인가?",
      "category": "POLITICS",

      "category": "CURRENT",
```

```json
{ "code": "SOLO_GROUP", "message": "그룹원이 2명 이상이어야 미션을 시작할 수 있습니다." }
```

### 2.3 `POST /api/v1/games/today/shown` — 진입 신호
문제 화면에 들어갈 때마다(패스로 바꾼 문제 포함 · 재접속 포함) 보낸다(D6). 그 번호에 지금 문제가 없으면 이 문제로 고정하고, 같은 문제면 멱등으로 같은 응답을 준다(GS10). 풀이 · 패스 신호는 여기서 고정된 문제에만 받는다(solve-signal).

**요청**
| 위치 | 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|---|
| 헤더 | `Cookie: access=<JWT>` | string | 예 | 유효한 access token | 로그인 쿠키 |
| 헤더 | `Content-Type` | string | 예 | `application/json` | |
| 본문 | `questionNo` | integer | 예 | `1` · `2` · `3` | 문제 번호 = 난이도(R-B5). 진행도 + 1 이어야 한다(GS9) |
| 본문 | `questionId` | string | 예 | `^[0-9a-f]{64}$` | 화면에 낸 문제 PK — 문제은행에서 그 번호 난이도의 문제 중 고른 것 |

**응답 `200`**
| 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `questionNo` | integer | 예 | `1` · `2` · `3` | 요청 값 그대로 |
| `questionId` | string | 예 | `^[0-9a-f]{64}$` | 이 번호의 지금 문제(= 요청 값) |
| `progress` | integer | 예 | 0~2 (= `questionNo − 1`) | 지금 진행도(GS13) |
| `missionStatus` | string(enum) | 예 | `NOT_STARTED` · `IN_PROGRESS` · `SUCCEEDED` · `CHEAT_FAILED` · `FAILED` | 내 미션 상태(MemberStatus). `200` 이면 언제나 `IN_PROGRESS` — 다른 값은 오류로 끝난다(GS9) |

**오류** (판정 순서는 GS9)
| code | HTTP | 조건 |
|---|---|---|
| `INVALID_REQUEST` | 400 | 본문이 JSON 이 아님 · 필드 없음 · `questionNo` ∉ {1,2,3} · `questionId` 가 64자 소문자 hex 가 아님 |
| `UNAUTHORIZED` | 401 | `access` 없음 · 만료 · 위조 |
| `GAME_NOT_OPEN` | 409 | 서버 시각 < 그날 07:00:00 |
| `SUBMISSION_CLOSED` | 409 | 서버 시각 ≥ 그날 08:00:00 |
| `NOT_PARTICIPANT` | 403 | 그날 그룹원이 아님 |
| `SOLO_GROUP` | 409 | 그날 그룹원이 1명 |
| `MISSION_NOT_STARTED` | 409 | 그날 문제은행을 받기 전(진행도 -1) |
| `MISSION_ALREADY_FINISHED` | 409 | 내 상태가 `SUCCEEDED` · `CHEAT_FAILED` |
| `QUESTION_MISMATCH` | 409 | 없는 문제 PK · 그 문제의 난이도 ≠ `questionNo` · 그 번호에 이미 다른 지금 문제가 고정됨(GS11) |
| `QUESTION_OUT_OF_ORDER` | 409 | `questionNo` ≠ 진행도 + 1 (이미 푼 번호의 늦은 재시도 포함) |

**요청 예시**
```bash
curl -s -X POST -b 'access=<JWT>' -H 'Content-Type: application/json' \
  -d '{"questionNo":1,"questionId":"032a4ed4d015d003a07a04124ce2b3513e71b986c3cf279104111ced399b366f"}' \
  http://localhost:8080/api/v1/games/today/shown
```
```json
{ "questionNo": 1, "questionId": "032a4ed4d015d003a07a04124ce2b3513e71b986c3cf279104111ced399b366f" }
```

**응답 예시** `200`
```json
{
  "questionNo": 1,
  "questionId": "032a4ed4d015d003a07a04124ce2b3513e71b986c3cf279104111ced399b366f",
  "progress": 0,
  "missionStatus": "IN_PROGRESS"
}
```

**오류 예시** `409` (1번에 이미 다른 문제가 고정됨)
```json
{ "code": "QUESTION_MISMATCH", "message": "지금 문제와 다른 문제입니다." }
```

## 3. 규칙
「서버 시각」은 모두 Redis `TIME`(마이크로초) 이다 — 앱 서버 · 클라이언트 시계로 판정하지 않는다. 경계 시각은 KST.

| id | 규칙 | 엔드포인트 |
|---|---|---|
| GS1 | **게임 날짜**: 게임 정보의 `date` 는 서버 시각이 KST 로 그 날짜 08:00:00 전이면 그 날짜, 08:00:00 이후면 다음 날이다(대기 화면이 다음 게임까지 센다). 문제은행 · 진입 신호의 날짜는 서버 시각의 KST 날짜다 | 게임 정보 · 전체 |
| GS2 | **시간 창**: 문제은행 · 진입 신호는 `07:00:00.000000 ≤ 서버 시각 < 08:00:00.000000` 만 받는다. 전이면 `GAME_NOT_OPEN`(D14), 후면 `SUBMISSION_CLOSED`. 08:00 제출 유예(D1)는 풀이 신호에만 있다 | 문제은행 · 진입 |
| GS3 | **그날 그룹원** = 소속 그룹에서 그 날짜 07:00:00 KST 전에 가입한 유저(R-G4 · R-G5). 07:00 에 확정되어 그날 안에는 바뀌지 않는다. 07:00 이후 가입자는 그날 `NOT_PARTICIPANT`, 다음 날부터 참가 | 전체 |
| GS4 | **1명 그룹**: 그날 그룹원이 1명이면 문제은행 · 진입 신호를 `SOLO_GROUP` 으로 거부한다(R-G6). 게임 정보는 `200` 이고 `members` 가 1개다 | 문제은행 · 진입 |
| GS5 | **미션 시작 1회**: 그날 처음 `200` 을 받은 문제은행 요청의 서버 시각이 `missionStartedAt` 이고 그 뒤로 바뀌지 않는다(동시 요청 · 다른 기기 포함). **지각** = `missionStartedAt > 07:00:03.000000`(D8 — 정확히 07:00:03 은 지각 아님). 지각은 응답에 없고 랭킹에만 쓴다. `QUESTIONS_EXHAUSTED` 로 끝나도 시작은 반영된다 | 문제은행 |
| GS6 | **은행 구성**: 난이도 1 · 2 · 3 마다, 은행을 만드는 시점에 이 유저의 출제 이력(진입 신호로 화면에 나간 문제 전부 — D6)에 없는 문제 중 20개를 무작위로(모자라면 있는 만큼) 준다(D10). 한 난이도라도 0개면 `QUESTIONS_EXHAUSTED`. 은행은 06:30 · 06:50 에 미리 만들어 둔 것이고, 없으면 요청 때 같은 규칙으로 만든다(D18) | 문제은행 |
| GS7 | **같은 날 같은 은행**: 같은 날 다시 받으면 같은 `missionStartedAt` 과 **같은 문제 목록(같은 순서)** 을 준다. 동시에 처음 요청해도 은행은 하나다 | 문제은행 |
| GS8 | **오늘 낸 문제는 빼지 않는다**: 같은 날 재요청의 은행에는 오늘 이미 화면에 낸 문제도 그대로 있다 — 클라이언트가 로컬 스토리지 기준으로 빼고 고른다(R-B6 · D18) | 문제은행 |
| GS9 | **진입 신호 판정 순서**(처음 걸리는 것으로 끝): 본문 검증(`INVALID_REQUEST`) → 시간 창(GS2) → `NOT_PARTICIPANT` → `SOLO_GROUP` → `MISSION_NOT_STARTED` → `MISSION_ALREADY_FINISHED` → 없는 PK · 난이도 ≠ 번호(`QUESTION_MISMATCH`) → 번호 ≠ 진행도 + 1(`QUESTION_OUT_OF_ORDER`) → 지금 문제 비교(GS10 · GS11) | 진입 |
| GS10 | **진입 신호 멱등**: 그 번호에 지금 문제가 없으면 이 문제로 고정하고 `200`. 이미 같은 문제가 고정돼 있으면 아무것도 바꾸지 않고 같은 `200`(재접속 · 재시도). 진행도가 오른 뒤의 같은 요청은 GS9 에 따라 `QUESTION_OUT_OF_ORDER` 다 | 진입 |
| GS11 | **번호마다 문제 하나**: 그 번호에 다른 문제가 고정돼 있으면 `QUESTION_MISMATCH`. 지금 문제를 바꾸는 길은 패스(solve-signal)뿐이고, 패스 뒤 교체 문제로 다시 진입 신호를 보낸다 | 진입 |
| GS12 | **출제 이력 중복은 거부하지 않는다**: 평생 이력에 이미 있는 문제로 진입 신호가 와도 GS9 ~ GS11 만 보고 `200` 을 준다(D15). 서버는 운영 로그로만 남긴다(사용자에게 보이지 않는다) | 진입 |
| GS13 | **진행도 표기**: 응답의 `progress` 는 0~3 이다(내부 -1 은 0). 진입 신호 `200` 의 `progress` 는 언제나 `questionNo − 1` | 진입 |
| GS14 | **문제은행 판정 순서**: 시간 창(GS2) → `NOT_PARTICIPANT` → `SOLO_GROUP` → 미션 시작(GS5) → 은행(GS6 · `QUESTIONS_EXHAUSTED`). 이미 완료(`SUCCEEDED` · `CHEAT_FAILED`)한 유저도 시간 창 안이면 `200` 으로 같은 은행을 받는다(재접속) | 문제은행 |
# SPEC — solve-signal

> 판 v1 · 2026-11-11 · 짝 문서: [HLD](../hld/solve-signal.md) · [LLD](../lld/solve-signal.md) · [SPEC](../spec/solve-signal.md) · [ORACLE](../oracle/solve-signal.md) · 근거: [PRD](../prd.md) v10 FR-4 · §5.4 ~ §5.7 · NFR-1 ~ NFR-3 · D1 · D9 · D14 · D17 · 공통 규약: [API 가이드](../api-guide.md)

**세 줄 요약**
- 엔드포인트 3개: 풀이 신호 `POST /api/v1/games/today/solves` · 패스 신호 `…/passes` · 부정 실패 신호 `…/failures`. 모두 쿠키 `access` 필수.
- 모두 멱등이다 — 이미 반영된 신호를 다시 보내면(마감 뒤 · 그룹 결과 확정 뒤라도) 같은 `200` 을 받는다. 그래서 네트워크 오류 · 타임아웃이면 같은 본문으로 재시도하면 된다.
- 풀이는 07:00 ~ 08:00 도착, 그리고 08:00:00 ~ 08:00:03 도착 중 `clickedAt` 이 08:00 전인 것만 받는다(D1). 패스는 08:00 전만, 실패 신호는 08:00 이후 무시(지금 상태로 `200`).

## 1. 엔드포인트
| 메서드 | 경로 | 설명 |
|---|---|---|
| `POST` | `/api/v1/games/today/solves` | 풀이 신호 — 푼 번호 · 문제를 보내 진행도 +1 |
| `POST` | `/api/v1/games/today/passes` | 패스 신호 — 지금 문제를 넘긴다(하루 1번) |
| `POST` | `/api/v1/games/today/failures` | 부정 실패 신호 — 로컬 스토리지가 빈 것을 알린다(R-F2) |

공통
- 인증: 쿠키 `access`(JWT 1시간). 없거나 만료 · 위조면 `401 UNAUTHORIZED`.
- 요청 헤더: `Content-Type: application/json`(`failures` 는 본문 없음 — 헤더도 필요 없다). 쿼리 없음.
- 오류 본문: `{ "code": string(ErrorCode), "message": string }`.
- 시각: ISO-8601, 오프셋 필수(api-guide §1). 서버는 `+09:00` 으로 보낸다.

### 1.1 공통 응답 형식
**SolveResponse** (풀이 `200`) · **FailureResponse** (실패 `200`) — 같은 형식
| 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `progress` | integer | 예 | 0 ~ 3 | 반영 뒤(또는 지금) 내 진행도. 시작 전(내부 -1)은 0 |
| `missionStatus` | string (MemberStatus) | 예 | `NOT_STARTED` · `IN_PROGRESS` · `SUCCEEDED` · `CHEAT_FAILED` · `FAILED` | 내 그룹원 상태 — 본인 기준이라 부정 실패면 `CHEAT_FAILED` 그대로 |
| `groupStatus` | string (GroupStatus) | 예 | `IN_PROGRESS` · `PENDING` · `SUCCEEDED` · `FAILED` | 그룹 상태 — SS14 |

**PassResponse** (패스 `200`)
| 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `passedAtQuestionNo` | integer | 예 | 1 · 2 · 3 | 오늘 패스를 쓴 번호(서버 저장 값) |
| `questionNo` | integer | 예 | 1 · 2 · 3 | 교체 문제로 진입 신호(`POST /games/today/shown`)를 보낼 번호 — 패스한 번호와 같다 |
| `progress` | integer | 예 | 0 ~ 3 | 지금 진행도(패스는 진행도를 바꾸지 않는다) |

**ErrorResponse** (모든 오류)
| 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `code` | string (ErrorCode) | 예 | §3 표의 값 | 클라이언트는 이것으로만 분기 |
| `message` | string | 예 | — | 사람용 문장 |

## 2. 요청 · 응답

### `POST /api/v1/games/today/solves`
- 인증: 쿠키 `access` 필수.
- 설명: 클라이언트가 정답을 맞힌 뒤(정답 판정은 클라이언트 — R-A1) 제출 버튼을 누르면 보낸다. 서버는 SS1 순서로 판정하고, 반영하면 진행도 +1 · 마지막 풀이 도착 시각 = 서버 도착 시각 · 그룹 판정 · 그룹원에게 실시간 전달을 한 번에 한다.

요청 본문
| 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `questionNo` | integer | 예 | 1 · 2 · 3 | 푼 문제 번호(= 난이도) |
| `questionId` | string | 예 | `^[0-9a-f]{64}$` | 푼 문제 PK — 그 번호의 지금 문제(진입 신호로 보낸 문제)여야 한다 |
| `successTime` | string (date-time) | 예 | ISO-8601 · 오프셋 필수 | 맞힌 시각(클라이언트). 기록만 하고 판정 · 랭킹에 쓰지 않는다(R-S5) |
| `clickedAt` | string (date-time) | 예 | ISO-8601 · 오프셋 필수 | 제출 버튼 클릭 시각(클라이언트). 08:00:00 ~ 08:00:03 도착분의 승인에만 쓴다(D1) |

응답
| 상태 | 본문 | 언제 |
|---|---|---|
| `200` | SolveResponse | 반영함 · 이미 반영된 신호(재시도) |
| `400` · `401` · `403` · `409` | ErrorResponse | §3 |

오류 코드
| code | HTTP | 조건 |
|---|---|---|
| `INVALID_REQUEST` | 400 | 필드 빠짐 · `questionNo` 가 1~3 밖 · `questionId` 형식 위반 · 시각 형식 위반 또는 오프셋 없음 |
| `UNAUTHORIZED` | 401 | `access` 없음 · 만료 · 위조 |
| `NOT_PARTICIPANT` | 403 | 그날 그룹원이 아님(07:00 이후 가입) |
| `SOLO_GROUP` | 409 | 그날 그룹원이 1명 |
| `MISSION_NOT_STARTED` | 409 | 문제은행을 받기 전(SS1-1) |
| `MISSION_ALREADY_FINISHED` | 409 | 부정 실패한 뒤 새 번호(SS1-3) |
| `GAME_NOT_OPEN` | 409 | 07:00 전(그날 명단이 아직 없음 — SS15) |
| `SUBMISSION_CLOSED` | 409 | SS3 의 시간 창 밖 |
| `QUESTION_OUT_OF_ORDER` | 409 | `questionNo > 진행도 + 1` |
| `QUESTION_MISMATCH` | 409 | `questionId` ≠ 그 번호의 지금 문제, 또는 진입 신호를 받은 문제가 없음 |

요청 예시
```bash
curl -X POST http://localhost:8080/api/v1/games/today/solves -b 'access=<jwt>' -H 'Content-Type: application/json' -d '{"questionNo":1,"questionId":"9f2c4e1a7b3d5f6081a2b3c4d5e6f708192a3b4c5d6e7f8091a2b3c4d5e6f708","successTime":"2026-11-12T07:03:10.412+09:00","clickedAt":"2026-11-12T07:03:11.020+09:00"}'
```
```json
{
  "questionNo": 1,
  "questionId": "9f2c4e1a7b3d5f6081a2b3c4d5e6f708192a3b4c5d6e7f8091a2b3c4d5e6f708",
  "successTime": "2026-11-12T07:03:10.412+09:00",
  "clickedAt": "2026-11-12T07:03:11.020+09:00"
}
```
응답 예시 `200` (반영 · 같은 본문의 재시도도 같다)
```json
{ "progress": 1, "missionStatus": "IN_PROGRESS", "groupStatus": "IN_PROGRESS" }
```
응답 예시 `200` (마지막 그룹원이 3번을 풀어 그룹 성공)
```json
{ "progress": 3, "missionStatus": "SUCCEEDED", "groupStatus": "SUCCEEDED" }
```
응답 예시 `409`
```json
{ "code": "SUBMISSION_CLOSED", "message": "제출이 마감되었습니다." }
```

### `POST /api/v1/games/today/passes`
- 인증: 쿠키 `access` 필수.
- 설명: 패스 버튼을 누른 즉시 보낸다(R-P2). 지금 문제를 넘기고 그 번호의 지금 문제를 비운다 — 클라이언트는 은행에서 같은 난이도의 다른 문제를 골라 `questionNo` 로 진입 신호를 보낸다. 진행도는 바뀌지 않는다. 그룹원 현황판에 「n번에서 패스」가 실시간으로 보인다.

요청 본문
| 이름 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `questionNo` | integer | 예 | 1 · 2 · 3 | 패스하는 번호 — 진행도 + 1 이어야 한다 |
| `questionId` | string | 예 | `^[0-9a-f]{64}$` | 넘기는 문제 PK — 그 번호의 지금 문제여야 한다 |

응답
| 상태 | 본문 | 언제 |
|---|---|---|
| `200` | PassResponse | 반영함 · 같은 번호 · 같은 PK 의 재시도 |
| `400` · `401` · `403` · `409` | ErrorResponse | §3 |

오류 코드
| code | HTTP | 조건 |
|---|---|---|
| `INVALID_REQUEST` | 400 | 필드 빠짐 · 범위 · 형식 위반 |
| `UNAUTHORIZED` | 401 | `access` 없음 · 만료 · 위조 |
| `NOT_PARTICIPANT` | 403 | 그날 그룹원이 아님 |
| `SOLO_GROUP` | 409 | 그날 그룹원이 1명 |
| `MISSION_NOT_STARTED` | 409 | 문제은행을 받기 전 |
| `PASS_ALREADY_USED` | 409 | 오늘 다른 번호 또는 다른 문제로 이미 패스함(R-P5) |
| `MISSION_ALREADY_FINISHED` | 409 | 미션 성공 · 부정 실패 뒤 |
| `GAME_NOT_OPEN` | 409 | 07:00 전 |
| `SUBMISSION_CLOSED` | 409 | 08:00:00 이후 도착(유예 없음) · 그룹 결과 확정 뒤 |
| `QUESTION_OUT_OF_ORDER` | 409 | `questionNo ≠ 진행도 + 1` |
| `QUESTION_MISMATCH` | 409 | `questionId` ≠ 지금 문제, 또는 지금 문제가 없음 |

요청 예시
```bash
curl -X POST http://localhost:8080/api/v1/games/today/passes -b 'access=<jwt>' -H 'Content-Type: application/json' -d '{"questionNo":2,"questionId":"0b7e3c9d1f2a4b5c6d7e8f90a1b2c3d4e5f60718293a4b5c6d7e8f90a1b2c3d4"}'
```
```json
{ "questionNo": 2, "questionId": "0b7e3c9d1f2a4b5c6d7e8f90a1b2c3d4e5f60718293a4b5c6d7e8f90a1b2c3d4" }
```
응답 예시 `200`
```json
{ "passedAtQuestionNo": 2, "questionNo": 2, "progress": 1 }
```
응답 예시 `409`
```json
{ "code": "PASS_ALREADY_USED", "message": "오늘 패스를 이미 썼습니다." }
```

### `POST /api/v1/games/today/failures`
- 인증: 쿠키 `access` 필수.
- 설명: 미션을 시작한 유저의 로컬 스토리지가 비어 있으면 클라이언트가 보낸다(R-F2). 서버는 그 유저를 `CHEAT_FAILED` 로 바꾸고(진행도는 그대로 — R-F4) 그룹 판정을 한다. 다른 그룹원에게는 그룹 결과 확정 전까지 「진행 중」으로 보인다(D2 — realtime-board).

요청: 본문 없음(보내도 무시한다). 쿼리 · 추가 헤더 없음.

응답
| 상태 | 본문 | 언제 |
|---|---|---|
| `200` | FailureResponse | 반영함 · 이미 부정 실패(재시도) · 미션 성공 뒤(무시 — D9) · 08:00 이후 · 그룹 결과 확정 뒤(무시) |
| `401` · `403` · `409` | ErrorResponse | §3 |

오류 코드
| code | HTTP | 조건 |
|---|---|---|
| `UNAUTHORIZED` | 401 | `access` 없음 · 만료 · 위조 |
| `NOT_PARTICIPANT` | 403 | 그날 그룹원이 아님 |
| `SOLO_GROUP` | 409 | 그날 그룹원이 1명 |
| `MISSION_NOT_STARTED` | 409 | 문제은행을 받기 전(07:00 전 포함 — D14) |

요청 예시
```bash
curl -X POST http://localhost:8080/api/v1/games/today/failures -b 'access=<jwt>'
```

```json
{ "progress": 1, "missionStatus": "CHEAT_FAILED", "groupStatus": "IN_PROGRESS" }
```

```json
{ "progress": 3, "missionStatus": "SUCCEEDED", "groupStatus": "IN_PROGRESS" }
```
응답 예시 `409`
```json
{ "code": "MISSION_NOT_STARTED", "message": "미션을 시작하지 않았습니다." }
```

## 4. 규칙
「도착 시각 `t`」 = 신호가 Redis 에 도착한 서버 시각(Lua 안 `TIME` — 앱 서버 시계 · 클라이언트 시각을 쓰지 않는다).

| id | 규칙 | 근거 |
|---|---|---|
| SS1 | **풀이 판정 순서** — 위에서부터 보고 처음 걸린 것으로 끝낸다: ① 시작 전 → `MISSION_NOT_STARTED` ② `questionNo ≤ 진행도` → 반영 없이 `200`(SS2) ③ 부정 실패 → `MISSION_ALREADY_FINISHED` ④ 시간 창(SS3) ⑤ `questionNo > 진행도 + 1` → `QUESTION_OUT_OF_ORDER` ⑥ 지금 문제 불일치 · 없음 → `QUESTION_MISMATCH` ⑦ 반영 | HLD §3 · §4 |
| SS2 | **풀이 멱등** — 같은 (날짜 · 유저 · 번호)는 처음 한 번만 반영한다. 이미 반영된 번호는 시간 창 · 그룹 결과와 상관없이 `200` + 지금 진행도 · 상태(재시도마다 같은 본문). 그룹원에게 다시 알리지 않는다 | FR-4 · R-S3 · R-S4 · NFR-3 |
| SS3 | **풀이 시간 창(D1)** — `t < 07:00:00` → `GAME_NOT_OPEN` · `07:00:00 ≤ t < 08:00:00` → 통과 · `08:00:00 ≤ t < 08:00:03` → `clickedAt < 08:00:00` 일 때만 통과, 아니면 `SUBMISSION_CLOSED` · `t ≥ 08:00:03` → `SUBMISSION_CLOSED` | D1 · R-D2 · NFR-1 |

| SS6 | **반영** — 진행도 +1 · 마지막 풀이 도착 시각 = `t` · 지금 문제 비우기. 진행도 3 이고 상태가 `IN_PROGRESS` 면 `SUCCEEDED` | R-S5 · §4.1 |
| SS7 | **그룹 판정** — 그날 그룹원 전원이 완료(`SUCCEEDED` · `CHEAT_FAILED`)가 되는 신호에서만 결과가 정해진다: 전원 `SUCCEEDED` → `SUCCEEDED`, 그 밖 → `FAILED`. 결과는 그룹마다 한 번만 기록 · 전달한다 | §4.2 · R-F6 · NFR-2 |
| SS8 | **패스 판정 순서** — ① 시작 전 → `MISSION_NOT_STARTED` ② 같은 번호 · 같은 PK 로 이미 패스 → `200`(SS9) · 다른 패스를 이미 씀 → `PASS_ALREADY_USED` ③ 성공 · 부정 실패 → `MISSION_ALREADY_FINISHED` ④ 시간 창(SS10) ⑤ `questionNo ≠ 진행도 + 1` → `QUESTION_OUT_OF_ORDER` · 지금 문제 불일치 · 없음 → `QUESTION_MISMATCH` ⑥ 반영 | HLD §3 |
| SS9 | **패스 멱등 · 하루 1번** — 같은 번호 · 같은 PK 의 재시도는 마감 뒤에 와도 같은 `200`. 그 밖의 두 번째 패스는 거부 | R-P1 · R-P5 |
| SS10 | **패스 시간 창** — `07:00:00 ≤ t < 08:00:00` 이고 그룹 결과가 없을 때만. 유예(D1)는 없다 | HLD §5 |
| SS11 | **실패 판정** — ① 시작 전 → `MISSION_NOT_STARTED` ② 미션 성공(D9) · 이미 부정 실패 · 마감 실패(`FAILED`) · `t ≥ 08:00:00` · 그룹 결과 확정 뒤 → 바꾸지 않고 `200` + 지금 상태 ③ 반영: `CHEAT_FAILED`, 진행도 그대로, 그룹 판정(SS7) | R-F2 · R-F4 · R-F6 · D9 · D14 · D17 |
| SS12 | **랭킹 시각** — 랭킹의 「푼 시각」은 `t` 다. `successTime` 은 기록만 하고 어디에도 쓰지 않는다. `clickedAt` 은 SS3 의 유예 구간 판정에만 쓴다 | R-S5 · R-D4 |
| SS13 | **응답 값** — `progress` 는 0~3(내부 -1 → 0). `missionStatus` 는 본인 기준 상태(부정 실패 본인에게는 `CHEAT_FAILED` — R-F5) | api-guide §1 · §2 |
| SS14 | **응답의 그룹 상태** — 그룹 결과 `SUCCEEDED` → `SUCCEEDED` · 즉시 실패 · 마감 실패 → `FAILED` · 결과가 없고 08:00 판정이 미뤄졌거나 `t ≥ 08:00:00` → `PENDING` · 그 밖 `IN_PROGRESS` | api-guide §2 · deadline-result HLD §3 |
